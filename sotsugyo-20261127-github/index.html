0512/8 ベータの定義 ─ 再確認

ベータとは、「他人に渡せる」状態のこと。

🎮 ゲームの状態
  • 必須機能と必要な素材が揃っている
  • 開始→操作→勝敗→終了まで通せる
  • 配布先のPC・端末で動く
📦 一緒に揃えるもの
  • 遊べる実行データと操作説明
  • 第三者のプレイ結果と不具合の記録
  • 直す項目の優先順位

基準は11/17から変わっていない。今日やることは、この定義の真ん中「開始→操作→勝敗→終了まで通せる」を、全員が自分のゲームで確かめることだ。

06ワーク① ─ 自分で1周チェック（15分）

まず自分のゲームを、最初から最後まで遊んでみる。

✎ 1周チェックリスト
  • タイトル（開始画面）から、止まらずにゲームが始まる
  • 操作の説明がなくても、最初の30秒で何をすればいいか分かる
  • 勝ち／負け／クリアのどれかで、必ず「終わる」
  • 終わったあと、タイトルに戻るか、もう一度遊べる
  • 途中で詰まる・落ちる・進めなくなる場所がない

1つでも外れたら、そこが今日直す場所だ。チェックは正直に。自分をごまかしても、ベータで他人が見つけるだけだ。

15分で自分のゲームを通す。外れた項目をメモさせる。
07通らなかったら ─ 直す順番

直す順番は「止まる場所」から。面白さは、その後だ。

優先症状今日の直し方
1落ちる／進めなくなる原因が分からなくても、その場面を避ける形に変えてよい。通ることが先
2終わらない（勝敗がつかない）仮でよいので、終了条件と結果画面を入れる
3始まらない／操作方法が伝わらない最初の画面に「押すキー」と「目的」を1行ずつ書く
4面白さ・見た目1〜3が全部片づいてから。今日は手を出さなくてよい
範囲を切るのも、直し方の1つだ。「全部入りで通らない」より「小さいけど通る」がベータになる。
08ワーク② ─ 撮って、見返して、判定する

卒業制作は一人での開発だ。だから、試遊は動画でやる。

▶ やり方（15分）
  • 自分のプレイを、タイトルから終わるまで通しで録画する
  • 撮った動画を「初めて見る人」のつもりで見返す
  • 止まった・迷った場所を、動画の時刻つきでメモする
✎ 判定と記録
  • 判定：1周「通った」か「通らなかった」か
  • 詰まった・止まった場所（時刻つき）
  • 自分でも気づかなかった、伝わらない表示

作っている本人は、自分のゲームを「知っている人」として遊んでしまう。動画を見返すと、知らない人の目で見られる。これが一人開発での試遊だ。撮った動画は下書きでよい。直したあと、最後にもう一度撮り直して提出する。

09ワーク③ ─ 直しリストと、今日の1 push

試遊の記録を、その場で「直しリスト」に変える。

✔ 手順は3つ

  • いちばん上の1つを、今日の授業の中で直す

リストの残り件数が、そのままベータまでの残りpush数だ。前回数えた数字と比べて、増えたか減ったかも見ておくこと。

14最後に ─ 動画を撮って提出する

今日の状態を、動画で残す。それが今日の提出だ。

🎬 撮影の仕様
  • タイトル画面 → 遊ぶ → 終わる（結果が出る）までを、通しで撮る
  • 長さは1〜3分が目安。編集でごまかさない、今日の状態そのまま
  • 途中で詰まったら、そこも含めて撮る。それが今日の記録だ
  • 撮れたら Slack #4d の今日のスレッドへ投稿する

動画は「できた証拠」であると同時に、次回の自分への申し送りだ。来週の自分が、今日どこまで行ったかを動画で思い出せる。ゲーム開発の授業と同じやり方で、卒業制作でも毎回残していく。
