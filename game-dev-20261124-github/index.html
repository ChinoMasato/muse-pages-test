今日の仕事は、push数を増やすこと。

今日の到達点

肉付けループを最低5周回し、1周ごとに必ずpushする。授業が終わる時点で、チームのリポジトリが「今日動いた」ことが一目で分かる状態にする。

作っただけでは、進んだことにならない。pushして初めて、進んだことが見える。
01今日やること

今日やることは、1つだけ

新しいことを始める日ではない。いまあるゲームを、遊んで・直して・pushする。それだけを繰り返す。

① 遊ぶ

いまの状態で実際に遊ぶ。気になった点を1つだけ選ぶ。

② 直す

選んだ1つだけを直す。新要素は足さない。数字（パラメータ）から触る。

③ pushする

直したら、その場でpush。ここまでで1周。pushしていない周は、終わっていない。

今日の合言葉 ― 「1周 ＝ 遊ぶ → 直す（1つ）→ 遊び直す → 記録 → push」

06なぜpush数か

pushしていないものは、止まって見える

11/20にこのチャンネルで伝えたとおり。確認はリポジトリを見て行う。古い状態のままなら、進んでいないものとして扱われる。

pushすると、得るもの
  • 自分のAIエージェントが最新のコードを見て、手伝える
  • チーム全員が、同じ最新状態で作業できる
  • 壊しても、前の状態にいつでも戻れる
  • 「いつ・何を・どれだけ進めたか」が自動で記録になる
pushしないと、起きること
  • ローカルで進めても、先生にもチームにも見えない
  • PCが壊れたら、その分は消える
  • 「やったはず」が証拠なしになり、評価にも残らない
だから今日は、完成度ではなく push数 を数える。push数は、回したループの数そのもの。

09アドバイス① ― 止まっていたチームへ

再起動は、1 pushから

18件の「11/20で不動」チームへの、今日の具体的な動き方。

やること
  1. 手元のプロジェクトを開き、動くかだけ確認する
  2. 何も直さず、まず現状をpushする（＝再起動の合図）
  3. 遊んで、直す点を1つ決めて、ループに入る
つまずきやすい所
  • 「もっと直してから上げたい」→ それが3日止めた原因。現状で上げる
  • pushでエラーが出る → その場で先生に声をかける。抱えたまま進まない
  • 誰のPCに最新があるか分からない → チームで最初に確認する
10アドバイス② ― 動いているチームへ

その調子で、もっと小さく刻む

動いた8件へのアドバイス。今日は「質」より「刻み方」を上げる。

2D-10・染谷蓮音君の Speed-Run（＋11件）の刻み方を見習う
  • 1回の変更を小さくし、動いたらすぐpush
  • 「直した→確認した→上げた」が短い間隔で回っている
  • 結果として、3日で他のチームの何倍も前に進んで見える
今日の伸ばし方
  • パラメータ調整だけの周も、遠慮なくpushする
  • 見た目（色・大きさ・速さ・音量）だけの周も立派な肉付け
  • 周回数を競う ― 今日6周が目標ライン
11アドバイス③ ― 何を直すか迷ったら

直す点の選び方 ― この順で探す

ループが止まる一番の理由は「何を直すか決まらない」こと。迷ったら上から順に。

優先見る所例
1遊んでいて引っかかる所操作が分からない／待たされる／見えない
2数字で変えられる所速さ・強さ・出現間隔・制限時間・スコア
3反応（juice）当たった時の音・光・揺れ・止まる感じ
4見た目色・大きさ・配置・文字の読みやすさ

新要素の追加は今日は禁止。いまあるものの「気持ちよさ」と「分かりやすさ」を上げるのが肉付け。
