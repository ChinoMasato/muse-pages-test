いちばん大事なルール

pushしていないものは、
「止まっている」ようにしか見えない。

手元で作っているだけだと

先生からは進捗ゼロに見える。前回11/20の評価も、リポジトリと動画の実物で確認した。自己申告だけでは点は動かない。

小さくてもpushすれば

「今日はここまで進んだ」が日付つきで残る。詰まった場所もコミットを見れば一緒に追える。就職のポートフォリオでも、そのまま制作の証拠になる。

作る → pushする → 見える。この3つで1セットだ。

05 / 18
pushは、階段だ

1 push = 1段。
14日あれば、14段登れる。

大きな完成を一度に見せる必要はない。今日の分を今日pushするだけで、ベータまでに14段分の差がつく。逆に、最後に一括で上げようとすると、途中で壊れたときにどこまで戻ればいいか分からなくなる。

pushは提出であり、同時にセーブポイントでもある。

06 / 18
pushの作法

作業の区切りごとに、
小さくpushする。

  • 機能が1つ動いたら、その場でpushする
  • 大きな変更をする「前」にもpushする（壊しても戻れる）
  • コミットメッセージは「何をしたか」を書く。日本語でよい
  • 授業の最後は、未完成でもpushしてから帰る
良い例：「ステージ2の敵配置を追加」「ジャンプの二段目を修正」 悪い例：「更新」「いろいろ」「最終版2」

「最終版」という名前のコミットが何個も並ぶのは、セーブポイントの使い方として逆だ。途中経過を全部残すのがGitHubの強み。
