01今日のゴール

提出物は、動画1本

タイトルから始めて、1周（結果が出るまで）を通して撮る。それが今日の提出物であり、評価の対象。

評価① ― 1周通っているか

タイトル → 遊ぶ → 終わり（クリア／ゲームオーバー／結果）→ もう一度遊べる、がつながっているか。

評価② ― 遊び方が伝わるか

初めて見る人が、説明なしで「何をするゲームか」「どう操作するか」を動画から読み取れるか。

評価③ ― 終わりまであるか

結果が出て、1周が閉じているか。途中で止まる動画は、そこで評価も止まる。

push数は、今日は数えない。見るのは「通して遊べるかどうか」と「完成度」。

08撮影の仕様

撮り方 ― ルールは4つ

この仕様は 11/25・11/26 の授業で伝えた通り。今日が提出日。

撮るもの
  • タイトルから始めて、1周（結果が出るまで）を通して撮る
  • 長さの目安は1〜3分
  • 撮影の直前に、最新の状態をpushしておく（動画とリポジトリの状態を一致させる）
ごまかさない
  • 編集でつないで「通ったこと」にしない
  • 詰まったら、詰まったまま撮る。それも評価材料になる
  • 音が出るゲームは、録画にも音が入る設定で撮る
通らない所を隠した動画より、通らない所が見える動画の方が、次の直しにつながる。
09撮影前チェック

本番の前に、この6点だけ確認する

リハーサル撮影で1回通し、この表で確認してから本番を撮る。

  • 最新の状態をpushした（動画に撮る状態 ＝ リポジトリの状態）
  • タイトル画面から始められる
  • 遊び方・操作が、画面から読み取れる
  • 終わり（クリア／ゲームオーバー／結果）まで行ける
  • もう一度遊べる（リトライできる）
  • 録画に音が入っている（音のあるゲーム）

1つでも欠けていたら、それが今日の前半に直す「1つ」。全部は直さない。優先順位は「終わりまであるか」が最優先。

提出したら、次は「見る側」に回る

提出

相互試遊の記録3点（見た動画について書く）
  1. 面白かった点
  2. 詰まった・分からなかった点
  3. 直すならこの1つ

この記録が、そのまま検証メモになる（企画 → 動くプロトタイプ → 検証メモの3点セット）。
