記録はこのスレッドへ

Slack の 「11/26 ゲーム開発 Push＆肉付けループ 記録スレッド」 に、1ステップごとに「何を変えたか」を1行残してから push してください。記録と push がセットで、今日の進捗になります。

なぜ小さく刻むのか

大きい変更は、壊れた時に原因が分からなくなる。15分ステップなら、壊れても直前の一つだけ戻せばいい。小さいステップの積み重ねが、一番速い進み方です。

ループの5手を板書代わりに残す。記録スレッドに1行書いてからpush、が今日の絶対ルール。
3ステップの例

15分ステップは、こんなに小さくて良い

パラメータ調整も立派な1ステップ
  • 敵の速度を 1.2倍 にする／ジャンプの高さを変える
  • 効果音を1つ足す／BGMを入れる
  • タイトルの文言・色を直す
  • スコア表示を出す／タイマーを出す
  • 詰まる所の当たり判定を少し広げる
大きくしない

「新システムを作る」は15分ステップではありません。今日は今あるものの肉付けに集中してください。

パラメータ一つでも良い、と明言する。ペースを上げることが目的なら、小さいステップの方が回数が稼げる。
4手段について

手段は問わない。ペースが大事

AIでも、手作業でも、ハイブリッドでも良い
  • AIに任せる部分があっても構いません
  • 手で書く方が速い所は手で書いてください
  • ただし「何を変えたか」は自分で言えること。言えない変更は入れない
評価されるのは結果

金曜に見るのは、通して遊べるかどうかと完成度です。作り方ではなく、前に進んだ量と質を見ます。

AI必須ではないことをはっきり言う。ただし変更内容を説明できることが条件。
5pushのルール

pushは「進捗の見える化」

記録してから、ステップごとにpushする
  • 15分ステップが終わるたびに、まず記録スレッド「11/26 ゲーム開発 Push＆肉付けループ 記録スレッド」へ「何を変えたか」を1行残す
  • そのあとpush。記録とpushはワンセット
  • 授業の終わりにまとめてpush、はしない
  • pushが止まっているチームは、詰まっている合図として見ます
止まったら

15分考えて分からなければ、そのステップは飛ばして次の小さいステップへ。1か所で止まり続けないこと。

pushの頻度そのものが今日のペースの指標になる。
