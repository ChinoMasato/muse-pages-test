📰今週のニュース ① ─ ビジネス＋IT 2026.11.24

PRのレビューから承認まで、AIに丸投げ。

アンソロピックが11月23日（米国時間）、「Claude Ship」をベータ提供開始。プルリクエスト（PR）のレビュー・修正・承認の判断までをAIエージェントに任せる仕組み。対象はClaudeのTeam／Enterpriseプラン、GitHubリポジトリ。

① Code Review（提供中）

PRをコードベース全体に照らして多角的に調べ、指摘を検証・分類して投稿。深さは Quick／Standard／Deep からリポジトリごとに選べる。

② PR Steward（ベータ）

CIの失敗・競合・レビュー指摘に対応し、プッシュのたびに「何を変えたか／どう戻すか」をコメント。承認とマージはしない設計。

③ Claude Approvals（ベータ）

チームがファイルに書いた承認ポリシーを適用し、定型的な変更はAIが自ら承認。重要な場面だけ人に回す。「より賢いCODEOWNERS」と説明されている。

使い方と実績
  • 開発者は新コマンド /ship：実行するとClaudeがプッシュ→PR作成→レビュー→失敗チェックへの対応まで進める
  • アンソロピック社内では、マージされたPRが2倍超に増え、差し戻し率は40％以上減（6〜9月）
  • 管理者はリポジトリごとの有効化・月次支出上限を設定可能。料金はトークン従量課金
「人は不要か？」への答え

記事の見出しの問い。でも中身を読むと、承認のルールを書くのは人で、推奨の始め方も「まず観察のみのモードで信頼できてから必須化」。つまり人の仕事が消えるのではなく、チェック係からルール設計者へ上がっている。今日のオマケ「ディレクター論」に直結する。

出典：ビジネス＋IT「PRのレビューから承認までAIに丸投げ　アンソロピック『Claude Ship』、人は不要か」（2026/11/24） https://www.sbbit.jp/article/cont1/188696 ※後半は会員限定のため、紹介は公開部分に基づく

授業の冒頭で紹介。ポイントは「承認までAIが進んだ」ことと、「それでもポリシーを書く人・観察モードで信頼を作る手順が残る」ことの両方。
📰今週のニュース ② ─ ビジネス＋IT 2026.11.19

Claude Code「Code Mode」─ AIがJSを書いてツール連携。

アンソロピックが11月12日、Claude Code v2.1.323に実験機能「Code Mode」を追加。これは、まさに今日のテーマ「ツール連携」の新しい実装方式だ。

従来：1つずつ呼ぶ
  • コマンド実行・ファイル編集などのツールを1回ずつ呼び、結果を読んで次を判断
  • 工程が増えるたびにAIとの通信往復が発生
  • 検索で拾った大量の不要なログまでAIの記憶領域（コンテキスト）に入り、遅く・高くなる
Code Mode：プログラムで一括実行
  • 指示を受けると、Claudeが裏側でJavaScriptのプログラムを書いて実行
  • 独立したコマンドの並行処理や、前のツールの結果を次のツールへ渡す連携を、1スクリプトで完結
  • データの選別（フィルタリング）をJSの中で行い、AIに返すのは「編集したファイルのパス」「テスト結果」など判断に必要な分だけ → トークン削減
具体例（記事より）

「設定値を書き換えて」と頼むと、AIが書いたコードが対象ファイルを検索してパスを特定し、修正し、テストを実行するところまでを一気に処理する。編集差分は従来どおり画面に出て、生成されたJS自体も Ctrl+O の履歴ビューアで監査できる。

注意点
  • 現時点では実験機能で、初期設定は無効（記事時点）
  • 対応はネイティブ版Claude Codeと対応モデル、ターミナル環境。デスクトップアプリやVS Code拡張などは対象外とされる
  • 企業利用では、権限モードごとにセキュリティチェックのタイミングが変わる点が焦点
誤解しないでほしい：今日の演習でも、ツールを呼び出すのは最初からエージェントの仕事だ。人がやるのは、連携の設計・発注・検証。Code Modeは、その呼び出し方自体が「1回ずつ対話」から「プログラムを書いて一括実行」に進化した段階だ。

09STEP 1-2 ─ ChatGPTでドット絵

背景チップとキャラを描く。

🗺 背景チップ用プロンプト例
16bit風ドット絵のタイルチップセットを作ってください。1タイル=32×32px相当で分割できる構図。含めるもの：草地、土、石畳、水辺の岸。色味とドットの粒度を統一し、継ぎ目が目立たないように。キャラクターや文字は入れない。
👤 キャラ用プロンプト例（重要）
ドット絵のゲームキャラクターを1体、全身で描いてください。正面を向いた直立ポーズ、全身が切れずに入る。背景は単色（白）で輪郭をはっきり。色数は少なめ、シルエットは単純に。武器やマントなどの細い揺れ物は付けない。※このままAutoSpriteに渡します

▲ 実際の検証用キャラ（ChatGPT生成 → 背景除去）verify_hero_01
剣＋盾＋マント付き = あえての「崩れやすい例」。今日はもっと単純に。

キャラの条件は「描きやすさ」ではなく「アニメ化しやすさ」で決める。
検証知見：入力は512〜1024px推奨、背景とキャラの分離が明確なこと、複雑な衣装・小物は一貫性を崩す。
10STEP 3 ─ AutoSprite（autosprite.io）

1枚を、アニメーションにする。

手順（ゲート方式）
  1. アップロード ─ キャラ画像を上げる（プロンプト生成は使わない）
  2. 基準ビュー確認 ─ 顔・配色・比率が原画と一致するか見る。崩れていたら画像を直す
  3. walkから生成 ─ 一番ごまかしが利かない動きで先に判定
  4. 書き出し ─ PNGシート＋JSONアトラス＋個別フレームを保存

▲ 透過チェックは暗・明の両背景で（実物の検証プレビュー）

⚠ 無料枠の配分がすべて

新規は15クレジット、1アニメ＝5クレジット → 3アニメまで、再生成の余裕はゼロ。推奨：walk → run → idle。8方向パック（15で全額）など高額メニューを先に押さない。※仕様は当日の画面表示を正とする。

配分は検証手順書（2026-11-20）そのもの。walk不合格なら残りを消費せず止め、入力を単純化して作り直す。止める判断も学び。

  • おかしい所は「素材／取り込み／コード」に分けてから直させる
Webで作ってもよい。完成条件を満たす方を選ぶ。exe化するならGodot＋Windowsビルドが本命。

実証最終工程 ─ Godotでexe化

🛠 Godot側の実装ポイント

  • 提出は前回どおり「exe＋スクショ」を #4dプログラマのスレッドへ

12発注文テンプレート

そのまま使える発注文。

自分のAIエージェントに貼る。視点とゴールは自分のゲームに書き換えること。要約せず、全文のまま渡す（条件が抜けるのを防ぐ）。

工程をつないで進め、各工程の成果物をファイルで残してください。 1. ブラウザでChatGPTを開き、ドット絵の背景チップと、全身・単色背景のドット絵キャラクター1体を生成して保存する。キャラはアニメ化しやすい単純なシルエットにすること。 2. ブラウザでAutoSprite（autosprite.io）を開き、キャラをアップロードして walk → run → idle の順に生成する。無料枠は15クレジットしかないので、walkのプレビューで顔や脚が崩れていたら、残りを消費せず止めて報告すること。 3. スプライトシートPNGとJSON、背景チップを使って、Godotでキー操作で動ける小さなゲームを作る。停止=idle、移動=walk、ダッシュ=run を切り替えること。スプライトはシートの余白ごと縮めると潰れるので、キャラが写っている範囲（Region）で切り出すこと。 4. 最後にGodotのWindows向け書き出しで単体exeにする。 5. 完成条件：exeと、キャラがアニメして動く画面のスクリーンショットを撮り、使った素材ファイルの一覧と一緒に報告すること。 ログインや課金が必要な画面で止まったら、自分で判断せず私に回してください。

🎁1オマケ ─ 毎日の仕事を自動化する

毎日ログインして、クレジットをもらう。

⏰ 毎朝、自動で回っている実例
  • Hi3D：デイリーチェックインで +10クレジット／日
  • AutoSprite：Daily Bonus で +3クレジット／日（今日使ったサービスの無料枠も、こうして貯まる）
  • Meshy：デイリーログインでクレジット付与（30日サイクルで日ごとに付与）

定期実行を予約しておけば、寝ている間にもタスクが進む。先生は毎朝、この回収をエージェントに任せている。

🛡 任せ方のルールが大事
  • やること：ログイン、ボーナス受取、残高の確認だけ
  • やらないこと：クレジットの消費・生成・購入はしない
  • 報告：普段は静かに。ログインできなくなった時だけ知らせる

「何をさせないか」まで決めて渡すのが、運用を任せるコツ。

使い道は「作る」だけじゃない。繰り返しの小さな仕事ほど、自動化が効く。
実例は2026-11-24から運用中。対象はHi3D／AutoSprite／Meshy。Tripoはデイリーボーナスが無いので対象外、という切り分けまで含めて実例。

工夫：別々に生成する

馬＋ジョッキーを1枚で描くと、Hi3Dで脚や体が癒着しやすい。だから馬（横向き・騎手なし）とジョッキー（Tポーズ）を分け、ゲーム側で騎乗させて組む。

実測

取得したGLBは馬・ジョッキーとも数十MB級・200万ポリゴン級。そのままではゲームに入らないので、軽量化とリグ付けが「つなぎ目」の仕事になる。

生成は2026-11-22。ダウンロードはログイン後の正規の経路で取得。Web版への組み込みでは旧モデルへのフォールバック問題も起きたので、実機確認までが工程、という話もできる。
🎁4オマケ ─ 音も、全部連携で作る

音楽・実況・効果音の3本立て。

🎵 Gemini → 音楽生成

Geminiの「音楽を作成」でシネマティックなインストBGMを生成。

  • 実例曲「BEYOND THE FIRST RIDGE」2分59秒
  • 静かな序奏 → 勇壮なクライマックス、ループ想定の構成を指定
  • 生成曲はゲームのBGMとして組み込み（同じ工程で作ったSuno版ファンファーレも併用）
🎙 AI Studio → 実況生成

実況セリフ29本をTTSで生成し、レースに組み込んだ。

  • 声が毎回変わらないよう、一度に生成して無音で分割する方式
  • 組み込み後は、発走・隊列・残り200m・着差などレースの状態で再生を分岐
  • 自動プレイ検証で、局面どおりに発火することを確認
🔊 ElevenLabs → SE生成

効果音は全15点を生成して組み込んだ。

  • UI音8点：カーソル／決定／キャンセル／エラー／開閉／取得／レベルアップ 他
  • 競馬SE7点：ゲート開放（5秒）／蹄音ループ（10秒）／大歓声（10秒）／拍手（12秒）／いななき／鞭／パドックの蹄音
音は「1曲作って終わり」ではない。局面に合わせて出し分ける仕組みまで作るのが組み込みの仕事。
いずれも2026-11-24の実作業。実況の分割方式は千野の提案。SEは長さまで全点確認済み。BGMの組み込み版はファイルの所在の都合でSuno版を使った点は、聞かれたら正直に答える。
🎁5オマケ ─ 役割の変化

プログラマの代わりから、ディレクターの代わりへ。

段階AIエージェントが担う仕事人に残る仕事
プログラマの代わり仕様どおりにコードを書く、直す、テストする仕様を決める、完成を判定する
スタッフの代わり素材を作る（絵・3D・音楽・声・効果音）、ツールを操作する、毎日の運用を回す素材の良し悪しを選ぶ、工程を設計する
ディレクターの代わり工程全体を計画し、道具と担当を割り振り、進捗を管理し、つなぎ目の不具合を切り分けて直す何を作るかを決める、面白いかどうかを判定する、公開の責任を持つ
今日の実例が全部これを示している：人間がコードを書いた場面はほぼ無い。やったのは企画・発注・選定・検証・判断 ─ ディレクターの仕事そのものだ。

だから学ぶべき力も変わる。コードを速く書く力より、工程を設計する力、道具を選ぶ力、出てきたものを判定する力。この授業で毎回やっている「発注文と完成条件」が、その訓練になっている。

締めの1枚。過度に断定せず「なりつつある」と言う。人の仕事が消えるのではなく、上流に移るという整理。学生の進路（プランナー・ディレクター志望）にも接続できる。
